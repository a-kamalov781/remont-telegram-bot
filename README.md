# Бот для сервисного бизнеса: запись и статус заказа в Telegram

Клиент записывается за 30 секунд и получает статус заказа в Telegram, без звонков «готово ли?». Мастер управляет заявками кнопками прямо в чате. Ниша выбирается одной настройкой: ремонт, химчистка, ателье, автосервис, ремонт бытовой техники.

**Демо-бот:** [@RemontPlusDemoBot](https://t.me/RemontPlusDemoBot). Выберите свой бизнес и пройдите сценарий за клиента и за мастера.

## Ниши

| `NICHE` | Бизнес | Кнопка записи | Спрашиваем об объекте | Статусы | Особенность |
|---|---|---|---|---|---|
| `repair` | Ремонт телефонов и ноутбуков | Записаться на ремонт | устройство | принята → визит подтверждён → принято в ремонт → диагностика → ждём запчасти → в работе → готово → выдано | |
| `drycleaning` | Химчистка | Сдать вещь в чистку | вещь | принята → на оценке → в чистке → готово, можно забирать → выдано | |
| `atelier` | Ателье | Записаться на примерку | изделие | принята → примерка назначена → в работе → готово, можно забирать → выдано | |
| `autoservice` | Автосервис | Записаться на диагностику | марка, модель, госномер | записан → на диагностике → согласование стоимости → ждём запчасти → в работе → готово, можно забирать → выдано | согласование суммы кнопками |
| `appliance` | Ремонт бытовой техники | Вызвать мастера | техника | принята → выезд подтверждён → мастер выехал → диагностика → ждём запчасти → идёт ремонт → ремонт завершён → работа сдана | адрес выезда |

Во всех нишах есть статус «отменено». Пресеты лежат в `bot/niches/`, новая ниша — это новый файл и строка в `bot/niches/__init__.py`.

**Согласование стоимости в автосервисе.** Мастер ставит статус «Согласование стоимости» и отправляет сумму: `/note 12 8 500 ₽, замена колодок`. Клиент получает сумму и кнопки «Согласен» и «Перезвоните мне», ответ приходит мастеру.

Сумма из такого `/note` записывается в отдельное поле заявки `price` и сохраняется при смене статусов. Задать или исправить её можно командой `/price 12 8500`, клиенту эта команда ничего не отправляет. Стоимость видна в `/order` и в отдельной колонке Google-таблицы, а статус готовности у клиента выглядит так: «Готово — к оплате 8 500 ₽».

## Что умеет

**Клиент**
- запись: услуга → день → свободное время → имя → телефон (кнопкой или вручную) → объект → описание проблемы → адрес (только `appliance`) → подтверждение
- статус своих заявок, цены, адрес и контакты
- автоматическое напоминание за N минут до визита
- уведомление при каждой смене статуса
- вопрос мастеру прямо в чат с ботом: текст, фото или файл

**Переписка.** Всё, что клиент пишет в бота вне сценария записи, приходит всем из `ADMIN_IDS` вместе с данными его заявки. Мастер нажимает Reply на этом сообщении, и ответ приходит клиенту. Текст переписки в базе не хранится, только связь «сообщение у мастера → клиент». В демо посетитель видит обе стороны сам, администратору такие сообщения не приходят. Антиспам: от одного клиента до мастера доходит не больше 10 сообщений за 10 минут, на остальные бот отвечает «Слишком много сообщений, мастер ответит на предыдущие».

**Мастер** (только из `ADMIN_IDS`)
- новая заявка приходит в личку с кнопками
- `/today`, `/tomorrow`, `/open` — списки записей
- `/order 12` — карточка с кнопками всех статусов
- `/note 12 текст` — комментарий клиенту, показывается только в текущем статусе и очищается при следующей смене статуса
- `/price 12 8500` — стоимость заявки (только автосервис)
- `/move 12 2026-11-05 14:00` — перенос визита, клиент уведомлён
- `/block` / `/unblock 2026-11-05 14:00` — закрыть слот (обед, выезд)
- `/stats` — счётчики

**Защита от ошибок**: слот нельзя занять дважды (проверка в момент выбора и в момент подтверждения), один телефон — одна запись на слот, прошедшие и заблокированные слоты не показываются.

**Google Sheets** (необязательно): каждая заявка и смена статуса дублируются в таблицу.

## Демо-режим

Один бот работает витриной сразу для всех ниш:

```
DEMO_MODE=true
DEMO_CONTACT=@ваш_ник
```

- На `/start` посетитель выбирает «Какой у вас бизнес?», сменить можно через `/niche`. Выбор хранится для каждого посетителя в таблице `demo_users`.
- Посетитель одновременно клиент и мастер своей заявки: ему приходит карточка мастера с кнопками статусов и подсказками, рядом он видит, что получает клиент.
- Чужие заявки недоступны, а занятость времени у каждого посетителя своя.
- Цены и услуги — из пресета выбранной ниши, шаг слота тоже. `SLOT_MINUTES` в демо не действует.
- После записи приходит пример настоящего напоминания перед визитом.
- После статуса «выдано» приходит сообщение с предложением и контактом из `DEMO_CONTACT`.
- Демо-заявки удаляются автоматически через 7 дней. В таблицу Google и в напоминания они не попадают.
- `/stats` для `ADMIN_IDS` показывает аналитику: сколько людей зашло, какие ниши выбрали, сколько записалось и дошло до конца. Действия самих `ADMIN_IDS` не считаются. Аналитика остаётся и после удаления заявок.

Заявки, созданные не в демо, остаются в базе, и напоминания по ним продолжают работать.

## Как развернуть под клиента

1. Создать бота у [@BotFather](https://t.me/BotFather), узнать Telegram ID мастера у [@userinfobot](https://t.me/userinfobot).
2. Заполнить `.env`, это занимает пару минут:
   ```
   BOT_TOKEN=...
   ADMIN_IDS=123456789
   NICHE=drycleaning
   BUSINESS_NAME=«Химчистка на Литейном»
   BUSINESS_ADDRESS=Санкт-Петербург, Литейный пр., 10
   BUSINESS_PHONE=+7 (812) 000-00-00
   WORK_START=10:00
   WORK_END=20:00
   WORK_DAYS=0,1,2,3,4,5,6
   ```
3. Поправить услуги и цены клиента: до первого запуска — в файле ниши `bot/niches/<ниша>.py`. Услуги попадают в базу один раз при первом запуске, поэтому потом их меняют в таблице `services` файла `data/bot.db`.
4. Запустить: `docker compose up -d --build`.

## Запуск за 3 команды

```bash
cp .env.example .env        # вписать BOT_TOKEN и ADMIN_IDS
pip install -r requirements.txt
python -m bot.main
```

Обновление старой базы происходит само при запуске: новые колонки добавляются, данные остаются, а существующие заявки и услуги становятся нишей `repair`. Перед обновлением всё равно сделайте копию `data/bot.db`.

## Деплой

### Docker (рекомендуется)
```bash
docker compose up -d --build
docker compose logs -f
```
База лежит в `./data` и переживает перезапуски.

### VPS без Docker (Ubuntu 22.04/24.04, 1 ГБ RAM хватает)
```bash
sudo useradd -r -m bot
sudo mkdir -p /opt/remont-bot && sudo chown bot:bot /opt/remont-bot
sudo -u bot bash -c 'cd /opt/remont-bot && git clone <repo> . && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && cp .env.example .env'
# отредактировать /opt/remont-bot/.env
sudo cp deploy/remont-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now remont-bot
sudo journalctl -u remont-bot -f
```

## Google Sheets (по желанию)
1. Google Cloud → создать сервисный аккаунт → скачать JSON в `credentials/service.json`.
2. Создать таблицу, дать доступ «Редактор» на email сервисного аккаунта.
3. В `.env`: `GOOGLE_CREDENTIALS_FILE=credentials/service.json`, `GOOGLE_SHEET_ID=<id из URL>`.

Если ключи не заданы, бот работает без таблицы.

## Тесты
```bash
pytest -q
```
Покрыто: логика слотов, нормализация телефонов, БД (антидубль, блокировки, напоминания, миграция старой базы), чтение настроек, корректность каждого пресета, сценарии записи через Dispatcher без сети для `repair`, `drycleaning`, `autoservice` и `appliance`, согласование стоимости, демо-режим (выбор ниши, карточка мастера, доступ к чужим заявкам, очистка, аналитика).

## Структура
```
bot/
  main.py        — запуск, планировщик напоминаний и очистки демо
  config.py      — настройки из .env
  db.py          — SQLite, заявки, услуги, слоты, аналитика демо
  keyboards.py   — кнопки
  texts.py       — тексты сообщений
  niches/        — пресеты ниш: услуги, статусы, тексты шагов
  handlers/
    client.py    — сценарий клиента (FSM)
    admin.py     — команды и кнопки мастера
    demo.py      — выбор ниши и действия посетителя над своей заявкой
    relay.py     — ответ мастера клиенту через Reply
  services/
    slots.py     — расчёт свободных слотов (чистые функции)
    notify.py    — уведомления клиенту и мастеру
    sheets.py    — выгрузка в Google Sheets
tests/           — pytest
deploy/          — systemd unit
```

## Ограничения
- Состояние диалога (FSM) в памяти: при перезапуске бота незавершённая запись сбрасывается, заявки в базе не теряются.
- Один бот = одна точка. Для сети нужна таблица филиалов.
- Напоминания проверяются раз в 5 минут.
